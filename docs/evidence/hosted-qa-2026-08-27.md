## 3. THE DEFECT THIS PASS FOUND — six surfaces say experiment data is ephemeral; it is durable

**This is the finding, and it was not findable any other way.**

`GET /api/about` serves `"persistence": "ephemeral"` from a **hardcoded literal**
(`apps/api/isaac_api/routes.py:16836`). In this deployment that is **false**, and the same
process says so: `/api/health` reports `experiment_storage.state: "durable"`, and §2.2 shows
records surviving 18 days.

### 3.1 Why no test caught it, and why that is not a testing failure

Locally `PGHOST` is unset, so `_postgres_available()` is false, the repository resolves to
`filesystem`, and `"ephemeral"` is **true**. Every one of the **6,133** backend and **4,713**
frontend tests is therefore correct to pass. **Only a Postgres-configured deployment can falsify
this claim, and until this session nobody had read that tab on one.**

### 3.2 The six sites

| # | Site | Text | Verdict here |
|---|---|---|---|
| 1 | `routes.py:16836` | `"persistence": "ephemeral"` | false |
| 2 | `/api/about` OpenAPI description | *"Every value is reused from the same authoritative source `GET /api/health` reads, so the two can never disagree."* | false — they disagree in production |
| 3 | Settings → Overview → Runtime Status | `Persistence  ephemeral`, under *"the runtime values below are read from the app itself"* | false, and the framing is false for this row specifically — it is a literal, not a runtime read |
| 4 | Settings → Overview → Boundaries → What Resets | *"The workspace is files on the server, not a database — discarded with the deployment's temporary storage."* | false for records |
| 5 | Settings → Data & Privacy → What Is Stored / What Resets | *"Two things are stored, both as files on the server"*; *"The workspace is not stored in a database … it is not durable … is discarded"*; and *"What the Workspace Contains: Experiments, their drafts, the answers you confirm …"* | false for records |
| 6 | `docs/deployment.md:35-37` | *"pod restarts reset state harmlessly"* | false for records; the `emptyDir` half is still true |

### 3.3 The precise conflation, which is what makes the fix non-trivial

Two things are true at once, and no surface currently distinguishes them:

- **The workspace directory IS ephemeral.** It is an `emptyDir` (`docs/deployment.md:35`), and it
  holds exported records, evidence sidecars and per-walkthrough directories. Those *are* lost on
  a pod restart.
- **Experiment records are NOT.** Experiments, their drafts and confirmed answers are in
  `isaac_experiments` in the app-owned PostgreSQL database, and persist.

The copy was written when both lived in the workspace. The 2026-08-07 durable-persistence lift
moved one of them and the copy did not follow.

### 3.4 Direction of error

It **understates** persistence, on the **data-governance** screen. A scientist is told their
experiment data is transient when it is durably stored. That is the opposite of the safe
direction, which is why this is ranked above a cosmetic copy defect.

### 3.5 The fix has an in-repo precedent

`apps/web/src/screens/ExperimentsHome.tsx` **already models this correctly**: `durabilityOf()`
reads `/api/health`'s live `experiment_storage.state` and selects one of three sentences
(`LABELS.storageDurable` / `storageEphemeral` / `storageUnavailable`, `lib/labels.ts:587-614`).
So the application contains the right derivation **one screen away** from the wrong one.

One qualification, measured: that correct sentence is rendered **only inside
`queue-empty-state`**, so on any deployment that already holds experiments — including this one —
**it never appears**. The correct claim is unreachable here while the incorrect one is always
visible. This also makes the Data & Privacy card's aside *"My Experiments states which before you
make one"* true only for a first-time, empty deployment.

Shape of the fix (not applied in this document):

1. `/api/about` → `"persistence": storage_status()["state"]`, which makes site #2's "can never
   disagree" **true by construction** rather than aspirational.
2. Settings copy branches on the three states and **separates record storage from the workspace
   directory**, so both true facts are stated instead of one false composite.
3. `docs/deployment.md` §State gains the same split.
