ISAAC — the scientist walkthrough, MEASURED 2026-08-19
=====================================================

WHAT THIS IS. The transcript of `/tmp/walkthrough.py` run against the application over
its own HTTP API, on an empty workspace, with every scientific value written out in the
script rather than harvested from a fixture. It is committed because the claim it
supports — "a scientist can create a record and finish it" — was FALSE on `main` at
`b118ed6` and is the reason PR #171 exists.

HOW TO REPRODUCE. The script is not committed (it is a probe, not a test); the same path
is pinned by `apps/api/tests/test_scientist_can_finish_a_record.py` and
`apps/api/tests/test_run_level_answers.py`, which is where a regression would be caught.
This file is the human-readable form.

WHAT IT DOES NOT SHOW.
  * The BROWSER. Every step here is an API call. The UI controls that make steps 2, 5
    and 10 answerable by a person (the QC verdict radios, the descriptor form, the
    series paste) are covered by `apps/web/src/__tests__/qc-verdict-control.test.tsx`
    and `structured-value-entry.test.tsx`, not by this.
  * The HOSTED deployment. Nothing here was run against `/krish`, which sits behind an
    Authentik edge this environment cannot authenticate to.
  * A SUCCESSFUL submit. Step 12 is a refusal, and it is the honest one: submission
    records an attributable declaration, and no trusted authentication boundary exists
    (E1). With an identity verifier armed it reaches the second gate — durable storage —
    and refuses there instead, because migrations 0003/0004 are not applied.

Ids differ per run (they are freshly minted ULIDs). Everything else is deterministic.
