## 1. Why this request exists, stated as a measurement rather than an opinion

BL15-2 is the confirmed first Historical Import pilot (`DEC-13`) and **that decision is closed.**
What is missing is data, and the gap is total rather than partial. Measured on `main` @ `2f9a1133`:

| Searched for | Found in the entire repository |
|---|---:|
| `.mac` files | **0** |
| `.xlsx` / `.xls` files | **0** |
| Real beamline logs, macro files, or run files | **0** |
| Production-derived historical source bundles | **0** |

Everything under `examples/` that *looks* like beamline material — `mock_campaign.csv`,
`raw_scan_listing.txt`, `webform_dump.txt` — is generated by
`scripts/make_synthetic_examples.py`. It contains fictional people (Ada Lovelace, Grace Hopper), a
fictional year-2099 session, and invented CuO / Cu K-edge numbers, and each file labels itself
`SYNTHETIC` in its own header. `openpyxl` is not a project dependency, so the spreadsheet parser
described in `docs/extraction.md` is a design document rather than shipped code operating on a real
workbook.

**So a parser written today would be written against assumptions.** `CLAUDE.md` §5 forbids that,
and it is the right rule here: a `.mac` grammar guessed from a synthetic fixture would look correct,
pass its own tests, and silently mis-map real science. **We would rather ship nothing than ship a
parser that confidently invents values.**

## 2. What would unblock the first wave

Ordered by how much each unblocks. **Even item 1 alone would unblock real work.**

### 1. Two or three complete historical experiments — the minimum useful corpus
For each, whatever exists of:

- the **directory tree** and full **filename listing** (this alone is parseable and valuable —
  filename and directory conventions are the single most deterministic signal in the corpus);
- the **macro / run / `.mac` files**, with their structure intact;
- the **spreadsheet or logbook** (Excel, CSV, or a Google Sheet export);
- any **README, notes, or text file** that a human wrote to explain the campaign;
- the **raw-data filename patterns** (not the raw data itself — see §4).

### 2. One case that is deliberately awkward
The easy cases teach us little. Specifically useful:

- an experiment spanning **multiple Runs**, so we can see how Run boundaries are actually expressed;
- a campaign where **an instrument or condition changed mid-way**, so we can see how that was
  recorded;
- a case where **two sources disagree** — a README saying one temperature and a spreadsheet saying
  another. That case is the whole reason the conflict model exists, and we currently have no real
  example of it.

### 3. The conventions, from someone who knows them
Written or verbal, whichever is easier:

- what the **filename fields** mean, in order;
- what the **directory levels** mean;
- how **Run numbers** are assigned, and whether they are reused;
- **column aliases** — what a spreadsheet header called `T` or `temp_set` actually is;
- **legacy vocabulary**: terms used then that map to ISAAC's current vocabulary now;
- any convention that changed over time, and roughly when.

### 4. Expert ground truth — the part only Angel can give
For each bundle in §1, the correct answer: **what the Experiments and Runs actually are**, and the
important metadata values, as a domain expert would record them. Without this we can measure that a
parser *ran*; we cannot measure whether it was *right*, and "the model seemed right" is not an
evaluation.

This is the single highest-value item after item 1, and it is the one that cannot be substituted.

## 5. What we explicitly do NOT need, and what not to send

- **Not the raw scan data.** ISAAC's official record stores **references and hashes, never file
  bytes** (`DEC-12` / `D5`, and `assets[]`'s own header says *"NO BYTES, EVER"*). Filename patterns
  and directory structure are what the parsers read.
- **Nothing that cannot be shared.** If a bundle contains unpublished results, personal data, or
  anything not cleared for this use, **please redact the values and keep the structure.** A `.mac`
  file with placeholder numbers but intact syntax is nearly as useful to a parser as the real one,
  and it carries none of the risk.
- **Please do not route real files through a personal AI account or a self-service connector.**
  That would be a governance workaround, not a shortcut (`DEC-22`, `DEC-23`). Model-assisted
  reconstruction over real scientific files is **blocked pending institutional data / provider /
  egress approval — blocked, not rejected** — and the seam is being built and tested against
  synthetic fixtures in the meantime so that approval is the only thing missing.

## 7. What happens when a bundle arrives

In this order, and not before:

1. **Inventory** what is actually there, by type and prevalence — measure the corpus rather than
   assume it.
2. **Inspect** real syntax, filenames and directory structure.
3. Implement deterministic parsers **only for observed conventions**.
4. Add a spreadsheet dependency **only if real data justifies it**.
5. Encode Beamline Profile rules **only where corpus evidence supports them** (`BL15-002`) — and a
   Beamline Profile must **never** become an unofficial validator; its job is repeatable source
   interpretation.
6. Build the expert-reviewed **gold corpus** from §4.
7. Measure: source-parsing coverage · Run-segmentation accuracy · field-mapping precision and
   recall · provenance coverage · conflict detection · ambiguity preservation · unmapped-content
   preservation · **fabricated-value rate** · incorrect-confident-mapping rate · scientist
   corrections required · curation time versus the manual workflow.

**The headline safety metric is fabricated-value rate, not fields filled.** A parser that fills
every field and invents three of them is worse than one that fills half and says so.
