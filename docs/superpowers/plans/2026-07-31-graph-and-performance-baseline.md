## Part 1 — Graph baseline decision

### 1.1 What was measured

| Fact | Evidence |
|---|---|
| `graphify-out/` is gitignored and local-only | `git check-ignore -v graphify-out` → `.gitignore:2:graphify-out/` |
| Local contents ≈ 10.4 MB | `graph.json` 2.5 M, `graph.html` 2.4 M, `manifest.json` 44 K, `GRAPH_REPORT.md` 76 K, `cache/` 4.2 M |
| Two committed artifacts | `memory-snapshot.json` 347,444 B · `memory-graph-detail.json` 493,985 B |
| Generation requires `graphify-out/` | `scripts/build_memory_snapshot.py` reads `graph.json` via `LocalGraphArtifactSource`; raises `SnapshotError` if absent |
| Graphify is a **user-local binary**, not a project dependency | `which graphify` → `/Users/krishverma/.local/bin/graphify` (v0.9.4, uv tool). No match in `pyproject.toml` or any `package.json` |
| Regeneration **uses an external model** | `graphify-out/cost.json` records a real run: `input_tokens: 89405`, `files: 50`. `docs/graphify-workflow.md:110` and the P36 closure doc both state community naming is an LLM pass (`--no-label` skips it) |
| Both committed artifacts are **currently fresh** | `build_memory_snapshot.py … --check` → exit 0, "no drift" on both |

### 1.2 The decision

Of the five evidence-backed options in the authorizing prompt, the chosen one is:

> **Option 4 — keep the graph point-in-time and non-blocking, with the limitation disclosed.**

**Reasoning, grounded rather than preferential:**

1. **Option 1 (institution-approved Graphify path) is not available to decide here.** It requires an
   institutional decision about sending repository content to an external model. That is precisely
   the class of decision the project already routes to a human, and no approval exists.
2. **Option 2 (`--no-label` deterministic generation) does not remove the blocker it appears to
   remove.** `--no-label` skips only the LLM *community-naming* pass. The extraction still depends on
   the user-local `graphify` v0.9.4 binary, which is not a declared dependency and cannot be installed
   in CI. A "reproducible in CI" mechanism that requires a binary CI cannot obtain is not reproducible.
3. **Option 3 (in-house deterministic graph builder) is a feature, not a baseline repair.** It would
   be a substantial new subsystem built to solve a problem that is currently *disclosed and harmless*.
   Building it under a baseline-restoration mandate would be exactly the scope expansion the
   authorizing prompt forbids.
4. **Option 5 (disable the graph) destroys working, tested, useful functionality** — Project Memory,
   Graph Browse/Explore, and the deep symbol layer, covered by `test_committed_snapshot.py` (449
   lines) and `test_memory_graph_detail.py` (1825 lines) — to fix a freshness property that is already
   honestly reported.
5. **The runtime already refuses to overstate freshness.** `GET {base}/api/graph/status` reports two
   *separate* axes — `memory_policy` and `indexed_sources` — and each degrades to `unknown` rather
   than manufacturing `current`. By design the hosted runtime can report `indexed_sources` as
   `current` or `unknown` but **never `stale`**, because the served source files are not shipped.
   That is a real limitation, and it is already surfaced rather than hidden.
6. **Drift is caught where it can be caught.** CI runs the committed-snapshot shape, provenance, and
   leak gates unconditionally, and the `--check` byte-drift gate runs wherever `graphify-out/` exists
   (locally). The pre-push preflight makes that a required step.

**Therefore the graph does not block baseline.** Its status is: point-in-time, locally regenerated by
a human, honestly reported at runtime, drift-gated in CI for the committed artifacts, and explicitly
**not** a source of truth (CLAUDE.md §2, §7).

### 1.3 A limitation discovered while writing this document

Adding the three new documents in this slice changed the committed snapshot by **two lines** — only
`CLAUDE.md`'s content hash. The new files did **not** enter the served set:

```
served paths:     201   (unchanged)
manifest entries: 200   (unchanged)
grep -c "2026-07-31-baseline" graphify-out/graph.json  ->  0
```

**Why:** the served-content manifest is derived from `graphify-out/graph.json`, not from the git
working tree. A file that is not in the graph cannot be in the served set, no matter that it is
committed and tracked.

**Consequence, stated plainly because it is easy to misread:** *Project Memory does not know about
documents created after the last graph regeneration.* The counts 201 and 200 are frozen at the graph's
point in time and will not grow as the repository does. Anyone reading "201 served files" as "every
relevant file in the repo" is reading it wrong.

This is a limitation, not a defect — the snapshot never claimed to be exhaustive, and the runtime
already refuses to overstate freshness (§1.2 point 5). But it was undocumented, and it is the most
concrete cost of the point-in-time decision: **the cost is invisibility of new material, not
incorrectness of old material.** Regenerating the graph is the only fix, and that requires the
user-local binary plus an unapproved external-model pass.

### 1.4 What this decision does *not* license

- It does not authorize sending repository content to an external model.
- It does not make Graphify a truth source.
- It does not permit committing `graphify-out/`.
- It does not permit a regeneration whose output has not been reviewed for leaks — the generator's
  fail-closed governance scan and the CI gates remain mandatory.

## Part 2 — Measured performance baseline

Measurement only. Per the authorizing prompt, only *measured, low-risk* improvements may follow, and
"do not add application-level compression when the edge already owns it."

### 2.1 Frontend bundle — `cd apps/web && npm run build`

| Asset | Raw | Gzip |
|---|---|---|
| `dist/index.html` | 0.46 kB | 0.29 kB |
| `dist/assets/index-*.css` | 180.45 kB | 25.75 kB |
| `dist/assets/index-*.js` | **633.57 kB** | **183.82 kB** |

Total build wall time 4.891 s (Vite portion 4.07 s).

**Finding (measured):** there is **no route-level code splitting** — one JS chunk, one CSS chunk.
Vite's own build output emits its >500 kB chunk warning. Every visitor downloads all of Assistant,
Project Memory, Graph, Validator, Schema browser, Statistics, and Settings to see any one screen.

**Severity: moderate, not urgent.** 184 kB gzip is unremarkable for an internal tool behind SSO on a
lab network. This is a real finding, not a theoretical one, but it is not a baseline blocker.

### 2.2 Runtime data transfer

| Fact | Evidence |
|---|---|
| The graph artifact is **not bundled** | `apps/web/src/lib/api.ts:585` fetches `/memory/graph/detail` from the API |
| It is **not re-read per request** | `routes.py:2358` uses `memory.get_default_detail_source()`, a memoized module-level reader with an mtime-keyed cache |
| Response size | ~494 kB uncompressed JSON |

**Finding (measured):** the largest single runtime payload is the deep graph detail response at
~494 kB, served uncompressed by the application.

### 2.3 Compression

**Measured:** `rg -in "gzip|brotli|compress" apps/api/isaac_api/` returns **no hits**. The app factory
(`apps/api/isaac_api/app.py:105-113`) registers exactly two middlewares — `ApiKeyAuthMiddleware` and
`CORSMiddleware`. Static assets are served by Starlette `StaticFiles`/`FileResponse` in `spa.py` with
no compression wrapper.

**Inferred / unverifiable here:** whether the nginx ingress compresses. `docs/deployment.md` mentions
the ingress only for forward-auth and path routing; no compression annotation appears. The ingress
manifests live in `ISAAC-DOE/isaac-k8`, **which is not in this repository and is Dean-owned**. It
cannot be checked from here.

**Decision: change nothing.** Adding `GZipMiddleware` would be precisely the "application-level
compression when the edge may already own it" the authorizing prompt warns against, and the question
is resolvable by one observation Krish can make in DevTools (see §2.5). Deciding it on a guess would
be the wrong call in either direction: redundant double-compression, or a missed 5× reduction.

### 2.4 Not a problem

- **Per-request snapshot re-parsing** — does not occur; readers are memoized with an mtime cache
  (`memory.py`).
- **Committed artifact staleness** — `--check` exits 0 on both artifacts.
- **Backend route count** — 36 routes; no evidence of an N+1 or per-request full-scan pattern.

### 2.5 Deferred recommendations (each needs one measurement first)
