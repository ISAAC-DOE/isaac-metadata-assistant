# Troubleshooting

Look here when a command exits non-zero or says something unexpected. Find the row, say the middle column, do the last.

| What happened | Say | Do |
|---|---|---|
| `isaac` not found / "need the ISAAC local import package" | "ISAAC isn't set up on this computer yet." | ask where their ISAAC folder is if `checkout-path.txt` is missing; give: `scripts/setup_isaac_local.sh` from that folder, then `--install-skill` and restart Claude Code (a skill installed for the first time needs a start to appear); `scripts/setup_isaac_local.sh --check` shows what is there without changing anything |
| import exit 3 | "I can't read that folder (not found, a shortcut, or no permission)." | ask for the real folder path; never follow shortcuts |
| import exit 4 ("--out is not empty") | "That working folder is already in use." | if it holds an earlier import of this beamtime, do not import: continue it (Step 2). Otherwise choose a new, empty folder outside the data. Never suggest `--force`: it overwrites the working folder and every answer in it is lost |
| import exit 5 | "ISAAC read the files but could not make a valid summary of them." | read the message (it may name a size limit: more runs or values than one working folder holds); report the exact message to the ISAAC team; do not retry blindly |
| a command prints a notice that says "re-import" (an older working folder) | "This working folder was made by an older ISAAC. To get <what the notice names>, the data must be read again into a NEW working folder, which starts with no answers." | ask before doing it; import into a new `--out`, never `--force`; if the folder already holds many answers, say what would have to be answered again |
| a beamtime with 0 runs | "No reader for these file types yet; N files were left unread." | go to Step 4 for what can be read; generic readers run automatically where present |
| `bundle show` (any kind, including a `question` id from `bundle questions`) / `excerpt` exit 6 | "That item doesn't exist in this bundle." | list again; ids change only when you re-import |
| a mutation exit 5 | "That change would leave the summary invalid, so nothing was saved." | read the message; fix the cause (usually a missing value with a decision) |
| `excerpt` exits 0 but its reply has `"refused"` (file changed, no longer in the folder, or inside a nested ZIP) | "I can't show that file's text: <the reason in its words>." | for a changed file, re-import into a new folder; otherwise read it another way (Step 4) |
| `decide` exit 2 | "That decision isn't allowed for this item." | read the allowed list in the message; for conflicts/missing values give `--value`. With `--only`: the question reaches none of the scopes you named |
| `decide --question <Q> --field <path>` exit 6: "No open question", though the question is listed | nothing to the scientist: it is my mistake | that question does not ask that field. `<isaac> bundle show <bundle> question <Q>` lists its `fields`; use the question whose fields include it (for the potential scale: the group's own optional-values question) |
| an approval is refused: "it is the scientist's Athena curve" (a working folder from an older ISAAC) | "Athena curves are never used for a record." | approve the ISAAC result the message names; if an Athena approval is in the way, reject it first, as the message says |
| `decide` exit 2: "not one of the schema's allowed values" | "That answer isn't one the record can hold." | show the allowed values it lists, map their words to one, say it back, and ask; nothing was recorded, and nothing was kept unless the reply says "kept as a vocabulary request" (only with `--as-said`, for their own exact word). A kept word exits 0 and the reply says so first (`vocabulary_request_kept`); no decision and no value was recorded for it. Without `--as-said` the exit is 2 and nothing is kept |
| `decide` exit 2: merge "needs --merge-with" or "names no record group" | "I need to know which group to merge it with." | list the groups again and name a live one |
| `process` exit 2: "Pass --source" | "ISAAC needs the original folder to read the scans." | run it again with `--source <the imported folder>`; nothing was written |
| `setup_isaac_local.sh` says the installed skill differs from the ISAAC folder's (`[stale]`) | "Your installed skill is out of date, I'm updating it." | `scripts/setup_isaac_local.sh --refresh-skill --skill-dir <skills>` from the ISAAC folder (`<skills>`: the folder holding this skill's folder; it copies the skill only, no download or install), then Read the file its `Skill written to:` line names and follow that text from Step 0 on; it wins where it differs. Once only: still `[stale]` after one refresh, or the refresh failed → stop, say the copy at that path could not be refreshed, continue with this text. No restart: every `reference/` file is read from disk when its step needs it, so it is the new one. A restart refreshes only the skill's one-line description in Claude Code's skill list, which changes nothing in this conversation |
| Step 0 `--check` says `[skipped]` for the skill, or this skill runs from somewhere else | (nothing yet: check first) | `diff -rq -x checkout-path.txt -x .DS_Store <folder>/.claude/skills/isaac-historical-import <this skill's folder>`; any output means stale: as the row above |
| `--check` says `[behind N commits] update check` | "Your ISAAC folder is N updates behind. Update now? It only changes the ISAAC code, not your data." | on yes, `scripts/setup_isaac_local.sh --update --skill-dir <skills>` (a `git fetch` and a fast-forward of GitHub's `main`, then `--refresh-skill`; when the Python dependencies changed it prints the command that refreshes the tools, a download, and does not run it), then re-read the skill as above. On no, continue and say the version in use (the commit the line names) |
| `--update` exit 3 "Not updated: …" | say the reason: "your ISAAC folder has local changes" / "is on another branch" / "has its own commits (diverged)" / "the update would replace files git does not track (they can be your data)" / "could not reach GitHub" / "GitHub did not answer" / "origin has no main branch (a fork?)" | nothing was changed; continue on the version in use. Never stash, reset, switch branch or force anything: the scientist (or whoever set the folder up) decides |
| `--check` says `[skipped] update check` (GitHub not reached or slow, origin has no `main`, not a git checkout, no `origin`) | the reason it gives, in a few words | continue: the check never fails; `--offline` skips it on purpose |
| `--update` exits non-zero but not 3 | "The update stopped: <its last line>." | suggest `scripts/setup_isaac_local.sh --check` to see where things stand; continue on the version in use |
| `process` exit 2: "processing not installed (processing_unavailable)" | "Curves and quality checks need an extra install." | `scripts/setup_isaac_local.sh --with-processing`; continue without it |
| `process` exit 2: "is a ZIP file" | "Processing reads the scans from a folder, not a ZIP. Could you unzip it outside the working folder and tell me where it is?" | ask the scientist to unzip it (you do not write files); confirm the unzipped folder is the data they approved, then `--source <the unzipped folder>` (the one folder inside, if everything in the ZIP is in one folder) |
| `import` says "N ZIP file(s) inside the imported ZIP ... not opened"; unread row `zip_inside_zip_not_opened` | "That ZIP has ZIPs inside it, and a ZIP inside a ZIP isn't opened, so their files weren't read. Could you unzip it and give me the folder? ZIPs inside a folder are opened." | ask the scientist to unzip it (you do not write files), confirm the folder is the data they approved, then import the folder into a NEW `--out` (a re-import is a new bundle) |
| validate exit 1 | "Some records aren't ready; here is why." | Step 8 table; its `by_reason`, `missing_required_by_field` and `not_exportable_first` say why without opening each file |
| export exit 1 | If its `outcome` wrote N > 0: "N records are ready in <records>; M groups still need something." If N = 0: "No record is ready yet." | read `outcome`, not the exit code (`records-and-validation.md`); explain the refusals from `refused_by_reason` and each `refused` row (every one is listed; Step 8), dry-run the written ones after the review (Step 10.4, the final check) |
| export exit 0 with "0 record(s) ready, refused 0 group(s)" | "No group is confirmed yet, so there was nothing to export." | exit 0 only means nothing was refused; go back to Step 5 |
| `annotate --from-readings` skips a finding: "run labels not in this bundle" or "names more than one run" | "I named a run in a way ISAAC can't place." | name each run by its `stem` or `run_id` from `bundle list <bundle> runs` (a `path` when two runs share a stem), then preview again |
| `annotate --from-readings` refuses a finding: `quote_not_found` (or `check-readings` exit 1) | nothing to the scientist yet: it is my mistake | open the cited lines again, copy the quote verbatim and put the locator on the line it is on (the reason says where it was found, if anywhere), then preview again; a scanned PDF page ("no text layer") or a file outside the folder cannot be checked, so no finding citing it is loaded: tell the scientist what it says instead (never cite a copy you made); "the PDF reader (pypdf) is not installed": run `scripts/setup_isaac_local.sh` |
| `annotate --from-readings --apply` exit 2: "this bundle does not record where that folder is" | nothing to the scientist | add `--root <the folder you imported>` |
| validate exit 1 with `nothing_validated` | "There's nothing to check yet: no group is confirmed." | Step 5 (confirm groups), then `build-records` |
| `bundle review` exit 1: "No records are built yet" or "The records changed since they were built" | "The records changed since I built them; I'm building them again so you review the final version." | `<isaac> bundle build-records <bundle>`, then `bundle review` again; nothing was recorded |
| `bundle review --accept --apply` exit 1: "The values changed since you were shown them" | "A value changed since I showed you the list; here is the new one." | run `bundle review` (same `--field`s) again, show it, and accept with its new `--listing` only on their yes; nothing was recorded |
| `bundle review --accept --apply` exit 2: "--apply needs --listing" | nothing to the scientist | run `bundle review`, show it, then use the accept command its `Next:` line gives |
| a second `--field` accepted from the first listing is refused (the records changed) | nothing to the scientist | after each `--apply`: `build-records`, then `bundle review` for what is left |
| `bundle review --field` exit 2: "No built record has the field" | nothing to the scientist | a mistyped path: pick one of the fields the message lists |
| `bundle review --accept` exit 2: "The bundle changed since it was read" | nothing to the scientist yet | run `bundle review` again, show what changed, and accept with the new `bundle_version` only on their yes |
| `bundle check` prints `STALE` (exit 1) | "This working folder was made by an older ISAAC; it is not broken." | `<isaac> bundle build-records <bundle>` re-derives it and logs what changed; say how many values it lists |
| any command exit 2: "The bundle changed since it was read" | "Something else (often the Local Imports page) changed it a moment ago; nothing was saved." | run `bundle questions` again, then repeat the answer if it still applies |
| `import --profile` exit 2 | "That reading profile doesn't exist." | drop `--profile` (the default `auto` chooses) |
| the bundle folder looks inconsistent | "Something in the working folder doesn't add up." | `<isaac> bundle check <bundle>`; exit 1 prints exactly what is wrong |
| the scientist asks to upload | "This build can only show what would be sent. Upload through the ISAAC portal." | `upload --dry-run` only |
| `upload --dry-run` exits 1 with `sent: false` | the final check: some records carry guesses or deductions not confirmed | ask its `question`; on "send them": the same with `--guesses-ok <digest> --by "<name>"`; on "check": `bundle review` |
| `--guesses-ok` refused: "the guesses changed since you were shown them" | the list changed (a new export) | run the dry run again without it and show the new list |
| `--guesses-ok` refused: "the records are older than your answers" | an answer was given after the export; the list changes only after a new export | `build-records`, `export` again, then the final check again |
| `--guesses-ok` refused: "does not say these records come from this bundle" | the export index is missing, or names another bundle | export again from the bundle (`--bundle` names it) |

Never retry a refused command with a flag that weakens a check, and never pass `process --params-file`
on your own to loosen a quality threshold: a changed parameter is the scientist's protocol decision,
made explicitly after `needs_changes`, never a way past a refusal. If something is unexpected, show the
exact message and ask the scientist how to proceed.
