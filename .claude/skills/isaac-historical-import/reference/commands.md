# Command cheat sheet (exact flags)

`<isaac>` is the command found in Step 0. Bundle commands print JSON; exit codes below.

| Purpose | Command |
|---|---|
| Read a folder or ZIP | `<isaac> import <folder> --out <bundle> [--profile auto\|<id>] [--force] [--record-local-root]` |
| A page of items | `<isaac> bundle list <bundle> runs\|conflicts\|candidates\|questions\|unread\|groups\|merge-candidates\|processed-outputs\|processing-results [--limit N ≤ 200] [--offset M] [--state S] [--no-values]` (Athena `.prj` projects are listed under `unread` with `read_by: isaac process`: the import has no reader for them, `process` reads them; `summary.md` and the import output say so) (`unread` is the files no reader claimed; the files a run reader kept beside a run WITHOUT opening them — `.rgn/.det/.exp`, a same-named folder's files, `binary/` originals — are counted apart, `not_listed.companion_not_opened` and "N files kept beside a run without any reader opening them" in the import output and `summary.md`, and `unread --all` lists them with `run_id`, `role`, `kept_by`) (`--state` is for `candidates` (value state) and `processing-results` (state); `--no-values` for `candidates` only; `--no-values` lists them without printing, so without exposing, any value) |
| One item | `<isaac> bundle show <bundle> run\|conflict\|candidate\|source\|question\|group\|merge-candidate\|processed-output\|processing-result <id>` (prints values). `source`: its `reader` block says which reader read the file, and `read_as` what it gave (a scan of run X, its header statements, the candidates it backs, by id and field) or the run it was kept beside unopened (a companion: `opened: false`, `role`). `question` takes the `Q-…` ids `bundle questions` prints (printed compact, as there, recording the same exposures) or an older fine-grained id; an unknown id is exit 6. |
| Re-validate the bundle itself | `<isaac> bundle check <bundle>` |
| What to cross-check | `<isaac> bundle crosscheck-plan <bundle> [--limit N] [--offset M]` (ids and locators, no values) |
| Raw source text at a target | `<isaac> bundle excerpt <bundle> <id> [--source <folder>]` (no parser value; `--source` is the folder or ZIP that was imported) |
| Record an AI reading | `<isaac> bundle annotate <bundle> --target <id> --value <text> [--json] --excerpt-locator "<where>" [--source-id <src>] --model "<model name>" [--blind] --rationale "<why>"` |
| Load a findings file | `<isaac> bundle annotate <bundle> --from-readings <file> --model "<model name>" [--apply]` (preview unless `--apply`; `<file>` in `<bundle>-notes/`) |
| Show the parser value, compare | `<isaac> bundle reveal <bundle> <id>` (marks the target as exposed; a scan start time is compared with the header's local clock time, `compared_as: local clock time`, its `parser.local_clock_start` shown) |
| Consolidated questions (use these) | `<isaac> bundle questions <bundle> [--scope experiment\|group:<id>\|run:<id>] [--blocking-only] [--limit N] [--offset M] [--skip-deferred] [--with-targets]` |
| Scientist decision | `<isaac> bundle decide <bundle> (--target <id> \| --targets-file <file> \| --question <Q> [--only group:<id>] [--field <path>]) --decision <d> [--value <v> [--as-said]] [--json] --by "<name>" [--orcid 0000-0000-0000-0000] [--note "<text>"] [--split-into '<json of run keys>'] [--merge-with <group ids> [--same-conditions]] [--qc-status <word> [--qc-note "<text>"]] [--element <symbol> --edge <edge> [--accept-shift <eV>]] [--positions N,N or last]` (refuses a value the field's schema rejects, records no decision, and lists the allowed values; a value refused only because it is not on the list is kept as a vocabulary request (`vocabulary_requests`, bundle 1.10.0; never a decision or a value) for `propose-terms` ONLY with `--as-said` (the scientist's own exact word), otherwise nothing is kept; a bulk call is refused whole; `--qc-status` only with a processing result and `approve`; `--element`/`--edge` only with a record group and `approve_calibration` (the calibration reference) or `set_absorber` (the absorber); `--accept-shift` only with `approve_calibration`, as the exact signed value its reply or `bundle show processing-result` (`calibration.would_apply[].shown`, `calibration.carried_shift.shown`) says, after the scientist accepts that size; with `--question`, only a decision in that question's `allowed_decisions`) |
| Metadata template (every `--out` in `<bundle>-notes/`) | `<isaac> bundle template export <bundle> --out <file.xlsx> [--force] [--no-suggestions] [--json]` (`ISAAC Suggestions` also lists the facility hints beside Facility Name, Facility organization and Beamline: the acquisition system's column names, the folder's name; a hint, never an answer); `<isaac> bundle template import <bundle> <file.xlsx> --by "<name>" [--orcid ...] [--apply] [--supersede] [--full] [--json]` (preview unless `--apply`; names each cell that replaces or contradicts a file reading); the scientist's OWN filled ISAAC template, only when they say to use it: `<isaac> bundle template adopt <bundle> <their.xlsx> --out <file.xlsx> [--by "<name>"] [--force] [--no-suggestions] [--json]` (contradicted values go to its `Disagreements` sheet, not the answer cells; pass `--by` only after the scientist says the sheet is theirs: with it, a value only off its field's list is also kept as a vocabulary request in that name; without it nothing is kept ("off-list values were not kept as requests: no name given"); and `template import --apply` keeps an off-list cell the same way; a beamline is compared by its first beamline-shaped token, a facility word and dash style ignored: `SSRL BL15–2` is `BL152`, `BL11-2` is not `BL1-12`) |
| Group runs into records | `<isaac> bundle group <bundle> [--regroup]` (proposes groups inside the bundle) |
| See the groups | `<isaac> bundle list <bundle> groups [--limit N] [--offset M] [--all]` (`--all` also applies to `merge-candidates` and `unread`; live groups, one row per line with `files`, `scans`, `reader`, `cannot_export_reason`; `--all` adds rejected, merged and split ones) · `<isaac> bundle list <bundle> merge-candidates` · `<isaac> bundle show <bundle> group <id>` |
| Process spectra (draft protocol) | `<isaac> process <bundle> --source <folder> [--group <id> ...] [--no-athena] [--params-file <json>]` (writes `processing/`; exit 2 and nothing written without a readable `--source`; `--group` redoes only the named groups and keeps the others, `kept_other_groups`) |
| Compose drafts | `<isaac> bundle build-records <bundle> [--full]` (counts and the first 3 drafts; `--full` prints every row; never `--test-marker`: self-tests only) |
| All gates, per draft | `<isaac> bundle validate <bundle> [--full]` (`by_reason`, `missing_required_by_field`, `not_exportable_first`, `pending_vocabulary` (field, term, groups: a value missing because the scientist's word waits on a vocabulary proposal), then `verdicts`; `warnings` shows the first 5, exportable groups' first (`group_exportable`), with `warnings_total` and, when some are left out, `warnings_full_list`: `validate --full` lists all) |
| Write passing records | `<isaac> bundle export <bundle> --out <records>` (safe to repeat: an unchanged record keeps its id; a changed one gets a new id and the old one moves to `<records>/isaac-export/superseded/`; one whose group is no longer exportable moves to `<records>/isaac-export/withdrawn/`; read its `outcome`: see `records-and-validation.md`; `exported[].warnings` lists a record's warnings that still apply (first 5, `warnings_total`), counted in `records_written_with_warnings`) |
| What would be uploaded | `<isaac> bundle upload <records> --dry-run [--portal-url <url>]` |
| Values outside the vocabulary, as draft term proposals | `<isaac> bundle propose-terms <bundle> [--out <file.json>] [--force \| --merge]` (prints parser values, so marks them exposed; sends nothing; each draft needs a description written by a person). Reads the vocabulary requests (an answer `decide` or the template refused only for being off the list) and the AI readings a scientist has not already answered with an allowed value. Per term: `runs`, `run_ids`, `scientist_notes` (their words, attributed), citations with a file name and run ids. A word naming an existing term is not drafted (`use_existing`, "use `RHE` (an existing term)"); a close one carries `check_existing`; a term with a space carries `ask`. `--merge` updates an existing `--out` file: new terms added, counts and citations updated, any description written in it kept, a term no longer found carried over (`carried_over`) |
| Pull text and images out of a document | `<python> -m isaac_api.local_import.extract <file> --out <dir> [--root <folder>] [--sheet <name> --rows-offset N --rows-limit M] [--show-limits] [--blocks]` (a cut sheet's `read_rest` gives the next page's command; `--blocks` prints a Word/PowerPoint file's blocks inline too, which `text_file` already holds) or `--from-bundle <bundle>/unread_files.json --root <folder> [--limit N]` |

Decisions by target kind: candidate / missing value / conflict: `confirm` `correct` `reject` `defer`;
record group: `confirm` `split` (`--split-into` lists of the group's `member_run_keys`, from `bundle show <bundle> group <id>`: one list per group to make, every run once; the reply's `split_into_groups` names the proposed groups it made) `merge` (needs `--merge-with` naming another live record group; `--same-conditions` when the scientist says the words the names differ in are labels, not conditions) `reject` `defer` `approve_calibration` (needs `--element` and `--edge`; a shift above 2 eV also needs `--accept-shift <the shift shown>`, e.g. `--accept-shift -8.6`, else refused with nothing recorded; the reply says the shift before anything is recorded; an approved result whose curve carries a shift that is now unconfirmed blocks its record until `--accept-shift <its size>` confirms it or that result is rejected), `set_absorber` (needs `--element` and `--edge`; changes nothing else about the group); merge candidate (`mc-...`): `keep_apart` (the groups are distinct; no group changes); the experiment (`--target experiment`): `set_counter_positions` (needs `--positions`), `set_not_counter_positions` (needs `--positions`, or `--question` on the counter question; grouping is unchanged), `defer` ("I don't know" to the counter question; grouping is unchanged, the question stays, deferred; takes no `--value`: the clock question's "I don't know" is `--question <Q> --decision defer`), `set_clock_time_zone` (needs `--value` with the IANA name, Area/Location or `UTC`, of the time zone the INSTRUMENT CLOCK that wrote the scan headers was set to; offsets and abbreviations are refused); processing result: `approve` (always with `--qc-status`: `valid`, `compromised`, `failed` or `pending` today; `decide` lists them if a word is wrong) `reject`
`needs_changes` `defer`, and `select_athena_version` (`--value` one of the result's `athena_versions[].version_id`; picks the scientist's Athena result of record, approves nothing). `confirm` and `correct` on a conflict or missing value need `--value`. The control mode (`context.electrochemistry.control_mode`) is an ordinary value: `correct --value <allowed mode>`, with `--field` on an optional-values question.

Exit codes: 0 ok · 1 not valid / not exportable (validate, export, check; for export see `records-and-validation.md`) · 2 usage or refused
decision (upload without --dry-run is also 2) · 3 input refused · 4 output refused · 5 bounds
exceeded, or the change would leave the bundle invalid (nothing written) · 6 not found.
