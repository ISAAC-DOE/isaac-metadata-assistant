# Command cheat sheet (exact flags)

`<isaac>` is the command found in Step 0. Bundle commands print JSON; exit codes below.

| Purpose | Command |
|---|---|
| Read a folder or ZIP | `<isaac> import <folder> --out <bundle> [--profile auto\|<id>] [--force] [--record-local-root]` |
| A page of items | `<isaac> bundle list <bundle> runs\|conflicts\|candidates\|questions\|unread\|groups\|merge-candidates\|processed-outputs\|processing-results\|athena-merges\|scan-notes [--limit N ≤ 200] [--offset M] [--state S] [--no-values]` (Athena `.prj` projects are listed under `unread` with `read_by: isaac process`: the import has no reader for them, `process` reads them; `summary.md` and the import output say so) (`unread` is the files no reader claimed; the files a run reader kept beside a run WITHOUT opening them — `.rgn/.det/.exp`, a same-named folder's files, `binary/` originals — are counted apart, `not_listed.companion_not_opened` and "N files kept beside a run without any reader opening them" in the import output and `summary.md`, and `unread --all` lists them with `run_id`, `role`, `kept_by`) (`athena-merges`, r7: the scientist's Athena merges that match no group, as the last `process` found them: label, projects, near groups, the groups sharing the project) (`--state` is for `candidates` (value state) and `processing-results` (state); `--no-values` for `candidates` only; `--no-values` lists them without printing, so without exposing, any value) |
| One item | `<isaac> bundle show <bundle> run\|conflict\|candidate\|source\|question\|group\|merge-candidate\|processed-output\|processing-result <id> [--full]` (prints values; `processing-result` includes the `scan_selection` and `scientist_quick_merges` blocks, `--full` every scan row and metric). `source`: its `reader` block says which reader read the file, and `read_as` what it gave (a scan of run X, its header statements, the candidates it backs, by id and field) or the run it was kept beside unopened (a companion: `opened: false`, `role`). `question` takes the `Q-…` ids `bundle questions` prints (printed compact, as there, recording the same exposures) or an older fine-grained id; an unknown id is exit 6. |
| Re-validate the bundle itself | `<isaac> bundle check <bundle>` |
| What to cross-check | `<isaac> bundle crosscheck-plan <bundle> [--limit N] [--offset M]` (ids and locators, no values) |
| Raw source text at a target | `<isaac> bundle excerpt <bundle> <id> [--source <folder>]` (no parser value; `--source` is the folder or ZIP that was imported) |
| Record an AI reading | `<isaac> bundle annotate <bundle> --target <id> --value <text> [--json] --excerpt-locator "<where>" [--source-id <src>] --model "<model name>" [--blind] --rationale "<why>"` (a reading that says the files state nothing, e.g. "not stated" or "unknown", is refused: record nothing then) |
| Load a findings file | `<isaac> bundle annotate <bundle> --from-readings <file> --model "<model name>" --root <folder> [--apply]` (preview unless `--apply`; `<file>` in `<bundle>-notes/`; every quote is checked against the cited file under `--root`, the folder you imported (default: the bundle's recorded root); `--apply` records no finding whose quote was not found, whose run is unknown or whose value is off its list, and refuses with no folder to check against) |
| Check the quotes only | `<isaac> bundle check-readings <bundle> <file> --root <folder>` (the same per-finding report; reads only; exit 1 when a quote was not found) |
| Scan notes | `<isaac> bundle list <bundle> scan-notes` (what the files say about a run's scans, from `scan_note` findings: AI readings, never decisions) · `<isaac> bundle show <bundle> run <id>` (its `scan_notes`) |
| Show the parser value, compare | `<isaac> bundle reveal <bundle> <id>` (marks the target as exposed; a scan start time is compared with the header's local clock time, `compared_as: local clock time`, its `parser.local_clock_start` shown) |
| Consolidated questions (use these) | `<isaac> bundle questions <bundle> [--scope experiment\|group:<id>\|run:<id>] [--blocking-only] [--limit N] [--offset M] [--skip-deferred] [--with-targets] [--include-outside-live-groups] [--each-group] [--no-context]` (`--each-group` also lists the per-group questions a beamtime question answers at once; each question carries a compact `context`, `--no-context` leaves it out, `bundle show <bundle> question <Q>` prints it in full: questions-and-decisions.md, "Context beside a question") |
| Scientist decision | `<isaac> bundle decide <bundle> (--target <id> [--target <id> ...] \| --targets-file <file> \| --question <Q> [--only group:<id> [--only group:<id> ...]] [--field <path>] [--same-reading]) --decision <d> [--value <v> [--as-said]] [--json] --by "<name>" [--orcid 0000-0000-0000-0000] [--note "<text>"] [--split-into '<json of run keys>'] [--merge-with <group ids> [--same-conditions]] [--qc-status <word> [--qc-note "<text>"] [--e0-measured]] [--element <symbol> --edge <edge> [--accept-shift <eV>]] [--scans "<scan id>,..."] [--positions N,N or last] [--same-sample [--names-differ-ok]]` (refuses a value the field's schema rejects, records no decision, and lists the allowed values; a value refused only because it is not on the list is kept as a vocabulary request (`vocabulary_requests`, bundle 1.10.0; never a decision or a value) for `propose-terms` ONLY with `--as-said` (the scientist's own exact word), otherwise nothing is kept; a bulk call is refused whole, naming every refused target and why; an open question that reaches none of the named `--only` scopes is refused, exit 2; an unknown question or group id, or a question no longer open, is exit 6; `--qc-status` only with a processing result and `approve`; `--element`/`--edge` only with a record group and `approve_calibration` (the calibration reference) or `set_absorber` (the absorber); `--accept-shift` only with `approve_calibration`, as the exact signed value its reply or `bundle show processing-result` (`calibration.would_apply[].shown`, `calibration.carried_shift.shown`) says, after the scientist accepts that size; with `--question`, only a decision in that question's `allowed_decisions`; `--only` once per scope answers several scopes with the one decision, all or nothing) |
| Metadata template (every `--out` in `<bundle>-notes/`) | `<isaac> bundle template export <bundle> --out <file.xlsx> [--force] [--no-suggestions] [--json]` (`ISAAC Suggestions` also lists the facility hints beside Facility Name, Facility organization and Beamline: the SPEC headers' fingerprint (account and column names), the acquisition system's column names, the folder's name; a hint, never an answer); `<isaac> bundle template import <bundle> <file.xlsx> --by "<name>" [--orcid ...] [--apply] [--supersede] [--full] [--json]` (preview unless `--apply`; names each cell that replaces or contradicts a file reading); the scientist's OWN filled ISAAC template, only when they say to use it: `<isaac> bundle template adopt <bundle> <their.xlsx> --out <file.xlsx> [--by "<name>"] [--force] [--no-suggestions] [--json]` (contradicted values go to its `Disagreements` sheet, not the answer cells; pass `--by` only after the scientist says the sheet is theirs: with it, a value only off its field's list is also kept as a vocabulary request in that name; without it nothing is kept ("off-list values were not kept as requests: no name given"); and `template import --apply` keeps an off-list cell the same way; a beamline is compared by its first beamline-shaped token, a facility word and dash style ignored: `SSRL BL15–2` is `BL152`, `BL11-2` is not `BL1-12`) |
| A filled question workbook (YOUR ANSWER column) | `<isaac> bundle answers import <bundle> <workbook.xlsx> --by "<name>" [--orcid <id>] [--folder <name> [--folder-differs-ok]] [--supersede] [--apply] [--json]` (preview unless `--apply`: each answered row as the exact `bundle decide` it is, with its cell and outcome, counts by tab; `yes`/`ok` accepts the shown suggestion, a typed value is a `correct` (an off-list word kept as a vocabulary request, as `--as-said`), blank and placeholders (`-`, `none`, `TBD` …) are skipped; an answer that would replace a DIFFERENT later decision is refused and that decision named, unless `--supersede`; rules, new questions and Athena merges are reported, never applied; `--apply` refuses a bundle in a `_runs…` folder: apply to a copy first, for real only on the user's word; see `reference/workbook-answers.md`) |
| Question site: make the cards | `<isaac> bundle site export <bundle> --out <folder> [--suggestions <file>] [--include optional] [--include deferred] [--include approvals] [--site-template <folder>] [--json]` (writes `<folder>/data/site-data.json` and its images, plus the site's own files when the template exists; `<folder>` must be outside every git repository and the bundle folder, exit 4 otherwise; by default the blocking questions and the processing question about beam damage; every card is checked by a dry run; the report lists the questions left out and why; see `question-site.md`) |
| Question site: read the answers back | `<isaac> bundle site import <bundle> <answers.json> --site-data <folder>/data/site-data.json [--apply] [--remember] [--note-read <card id>] [--json]` (preview unless `--apply`: applied, already recorded, refused with the reason, notes to read, cards no longer asked; recorded by `<name> (question site)`; `--apply` is refused inside a folder named `_runs…`, exit 4; a second run records nothing; an answer with a note on a card for several measurements is held until `--note-read <card id>`; `--remember` keeps the answers in the answer memory only when the scientist turned it on) |
| Earlier answers (opt-in, this computer only) | `<isaac> answer-memory on --by "<name>"` (only on the scientist's yes) · `<isaac> answer-memory off` · `<isaac> answer-memory status` · `<isaac> answer-memory list [--field <path>] [--beamtime <folder name>] [--limit N] [--offset M]` · `<isaac> answer-memory forget (--entry <id> \| --beamtime <folder name> \| --all)` · `<isaac> answer-memory learn <bundle> --by "<name>"` (only on the scientist's yes: also remembers the answers a bundle recorded before it was on, or forgotten since; only while on. Otherwise only an answer recorded while on is remembered, at that moment; never a dry run or a preview) · `forget --all` also removes an unreadable memory file (ask first). A matching question shows `earlier_answers`; confirm one with `<isaac> bundle decide <bundle> --question <Q> --decision correct --value <that value> --from-earlier-answer <entry_id> --by "<name>"` (refused for another value or field). File: `~/.isaac/answer-memory.json` (`ISAAC_ANSWER_MEMORY` overrides; never inside the repository or a bundle) |
| Group runs into records | `<isaac> bundle group <bundle> [--regroup]` (proposes groups inside the bundle) |
| See the groups | `<isaac> bundle list <bundle> groups [--limit N] [--offset M] [--all]` (`--all` also applies to `merge-candidates` and `unread`; live groups, one row per line with `files`, `scans`, `reader`, `needs_care`, `cannot_export_reason`; `--all` adds rejected, merged and split ones) · `<isaac> bundle list <bundle> merge-candidates` · `<isaac> bundle show <bundle> group <id>` |
| Process spectra (draft protocol) | `<isaac> process <bundle> --source <folder> [--group <id> ...] [--no-athena] [--params-file <json>]` (writes `processing/`; exit 2 and nothing written without a readable `--source`; `--group` redoes only the named groups and keeps the others, `kept_other_groups`; a params file may hold `exclude_scans` and, r6, `athena_match`, which ties a scientist's merge to a group on their answer, `athena_match_not` (their "no" for one group) and, r7, `athena_ignore` (`[{"project": …, "athena_group": …}]`: a merge that is no group's, no longer listed); the reply's `athena_unmatched_merges` lists the first 10 merges that match no group) |
| Compose drafts | `<isaac> bundle build-records <bundle> [--full]` (counts and the first 3 drafts; `--full` prints every row; never `--test-marker`: self-tests only) |
| All gates, per draft | `<isaac> bundle validate <bundle> [--full]` (`by_reason`, `missing_required_by_field`, `not_exportable_first`, `pending_vocabulary` (field, term, groups: a value missing because the scientist's word waits on a vocabulary proposal), then `verdicts`; `warnings` shows the first 5, exportable groups' first (`group_exportable`), with `warnings_total` and, when some are left out, `warnings_full_list`: `validate --full` lists all) |
| Write passing records | `<isaac> bundle export <bundle> --out <records> [--full]` (every refused, withdrawn, replaced or restored row, and every record with a warning of its own, in full; of the repeated ok rows the first 3, `schemas_used` once at the top; `--full` prints every row; safe to repeat: a record whose body is unchanged keeps its id, also when only its evidence changed (`evidence_refreshed`, `evidence_changed`: only the sidecar is rewritten); a changed one gets a new id and the old one moves to `<records>/isaac-export/superseded/`; one whose group is no longer exportable moves to `<records>/isaac-export/withdrawn/`; read its `outcome`: see `records-and-validation.md`; `exported[].warnings` lists a record's warnings that still apply (first 5, `warnings_total`), counted in `records_written_with_warnings` for records written now and `records_ready_with_warnings` for every ready one; `records_written` counts new or replacing records only, `records_ready` all) |
| What would be uploaded | `<isaac> bundle upload <records> --dry-run [--portal-url <url>] [--full]` (every replacing record and every one with a note of its own in full; of the rest the first 3, with `records_total`; `--full` lists every record) |
| Values outside the vocabulary, as draft term proposals | `<isaac> bundle propose-terms <bundle> [--out <file.json>] [--force \| --merge]` (prints parser values, so marks them exposed; sends nothing; each draft needs a description written by a person). Reads the vocabulary requests (an answer `decide` or the template refused only for being off the list) and the AI readings a scientist has not already answered with an allowed value. Per term: `runs`, `run_ids`, `scientist_notes` (their words, attributed), citations with a file name and run ids. A word naming an existing term is not drafted (`use_existing`, "use `RHE` (an existing term)"); a close one carries `check_existing`; a term with a space carries `ask`. `--merge` updates an existing `--out` file: new terms added, counts and citations updated, any description written in it kept, a term no longer found carried over (`carried_over`) |
| Pull text and images out of a document | `<python> -m isaac_api.local_import.extract <file> --out <dir> [--root <folder>] [--sheet <name> --rows-offset N --rows-limit M] [--show-limits] [--blocks]` (a cut sheet's `read_rest` gives the next page's command; `--blocks` prints a Word/PowerPoint file's blocks inline too, which `text_file` already holds) or `--from-bundle <bundle>/unread_files.json --root <folder> [--limit N]` |

Decisions by target kind: candidate / missing value / conflict: `confirm` `correct` `reject` `defer`;
record group: `confirm` `split` (`--split-into` lists of the group's `member_run_keys`, from `bundle show <bundle> group <id>`: one list per group to make, every run once; the reply's `split_into_groups` names the proposed groups it made) `merge` (needs `--merge-with` naming another live record group; `--same-conditions` when the scientist says the words the names differ in are labels, not conditions) `reject` `defer` `approve_calibration` (needs `--element` and `--edge`; a shift above 2 eV also needs `--accept-shift <the shift shown>`, e.g. `--accept-shift -8.6`, else refused with nothing recorded; the reply says the shift before anything is recorded; an approved result whose curve carries a shift that is now unconfirmed blocks its record until `--accept-shift <its size>` confirms it or that result is rejected), `set_absorber` (needs `--element` and `--edge`; changes nothing else about the group), `set_scan_decision` (isaac.xas.v1: `--value keep` or `--value drop` with `--scans` naming the scans by the ids the result's `scan_decisions` rows give; the scientist's keep / drop overrides the scan-decision rule for those scans; it changes no group status, and `process --group <id>` re-processes the group into a new result), `set_dose_reading` (isaac.xas.v1: `--value beam_damage`, `first_scan_settling` or `not_beam_damage`, the scientist's reading of a within-spot change the result asks about (`dose_reading_question`); also on `--target experiment` for the whole beamtime, a group's own reading wins; re-process to apply it), `set_role` (`--value sample`, `reference` or `alignment`: the scientist's word on what the group is, over the role grouping proposed from a `foil` / `align` name token, a header or the engine's class; latest wins, no status changes; e.g. a proposed reference that is a sample: `--target <group id> --decision set_role --value sample`); merge candidate (`mc-...`): `keep_apart` (the groups are distinct; no group changes); the experiment (`--target experiment`): `set_counter_positions` (needs `--positions`), `set_not_counter_positions` (needs `--positions`, or `--question` on the counter question; grouping is unchanged), `defer` ("I don't know" to the counter question; grouping is unchanged, the question stays, deferred; takes no `--value`: the clock question's "I don't know" is `--question <Q> --decision defer`), `set_clock_time_zone` (needs `--value` with the IANA name, Area/Location or `UTC`, of the time zone the INSTRUMENT CLOCK that wrote the scan headers was set to; offsets and abbreviations are refused); processing result: `approve` (a result flagged `athena_e0_possibly_fixed` also needs `--e0-measured`, only when the scientist says that E0 was measured; always with `--qc-status`: `valid`, `compromised`, `failed` or `pending` today; `decide` lists them if a word is wrong) `reject`
`needs_changes` `defer`, and `select_athena_version` (`--value` one of the result's `athena_versions[].version_id`; picks the scientist's Athena result of record, approves nothing). `confirm` and `correct` on a conflict or missing value need `--value`. The control mode (`context.electrochemistry.control_mode`) is an ordinary value: `correct --value <allowed mode>`, with `--field` on an optional-values question.

Exit codes: 0 ok · 1 not valid / not exportable (validate, export, check; for export see `records-and-validation.md`) · 2 usage or refused
decision (upload without --dry-run is also 2) · 3 input refused · 4 output refused · 5 bounds
exceeded, or the change would leave the bundle invalid (nothing written) · 6 not found.
